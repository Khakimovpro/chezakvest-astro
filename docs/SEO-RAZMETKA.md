# SEO-разметка

Канонический адрес сайта — `https://xn--80aehcht5ci1b.xn--p1ai/`. Все canonical URL, ссылки в JSON-LD и Open Graph URL должны использовать этот HTTPS-хост и завершающий слеш у пути.

## Какие типы используются

| Страница | Разметка | Почему |
| --- | --- | --- |
| Все индексируемые страницы | `Organization`, `WebPage` | Единые проверенные реквизиты компании и описание текущей страницы. `Organization` содержит логотип, телефон, контакт для бронирования и реальный профиль VK. |
| Страница с подтверждённой видимой иллюстрацией | `ImageObject`, связь `primaryImageOfPage` | Изображение размечается, только если тот же локальный asset действительно присутствует в отрисованном body. Snapshot может показывать другой Tilda-asset вместо `hero.bg`/`howto.photos`; тогда разметка изображения и поле `image` сущности удаляются. Сейчас точное совпадение есть на 5 страницах: главной, `/igra-v-kalmara-lend/`, `/minecraft-lend/`, `/new-year/`, `/vypusknoj-kalmar/`. |
| Главная | `WebSite` | Описывает сайт и связывает его с `Organization`. |
| Внутренняя индексируемая страница | `BreadcrumbList` | Повторяет видимые хлебные крошки. Главная — единственное исключение. |
| Квест или VR-игра | `Service` | `serviceType` различает обычный квест и четыре страницы, прямо названные `VR-игра`. Название, возраст аудитории и описание с видимыми длительностью и числом игроков берутся из JSON страницы. У `Service` нет отдельных свойств Schema.org для длительности квеста и числа участников, поэтому для них не используются чужие свойства с неподходящим доменом. `venueSlug` сам по себе не доказывает видимость связи: пока основной контент квестов не называет выбранную площадку, `availableChannel` не выдаётся. |
| Площадка | `EntertainmentBusiness` | Это наиболее точный подтип `LocalBusiness`: адрес и координаты берутся из `venues.json`, телефон — из `site.json`, часы работы — из видимого футера. `hasMap` выдаётся только когда точная ссылка маршрута есть в отрисованном body; сейчас это 4 из 9 площадок. Поле `image` сейчас не выдаётся: пути фотографий из JSON не совпадают с фактически отрисованными snapshot-asset. Дни недели не размечаются: в источнике их нет. |
| Праздничная программа | `Service` | Описывает реально показанную услугу. `Offer` появляется только при наличии видимой цены в блоке пакетов; поле `priceFrom` само по себе источником не считается. Валюта и цена размечаются, а наличие мест и включение НДС — только если для них появится видимый источник. |
| Каталог и страница категории | `CollectionPage` с `ItemList` | Элементы повторяют видимые карточки и ведут на канонические страницы. |
| Страница с видимым FAQ | `FAQPage` | Вопросы и ответы должны дословно соответствовать отрисованному блоку. Сейчас условие выполняется только на `/new-year/`. |
| Страница с проигрываемым видео и подтверждённой датой публикации | `VideoObject` | Источник разметки — фактически выбранное тело страницы. У snapshot это Rutube-плеер с `data-source-video-id`; схема получает его официальные название, описание, дату, длительность и `embedUrl`, а `thumbnailUrl` совпадает с показанной локальной копией подтверждённого Rutube preview. У нативного тела источником остаётся локальный MP4, который получает `contentUrl`. Сейчас `VideoObject` есть на 28 индексируемых snapshot-страницах квестов. `/kvest_v_realnosti_sherlock_holms/` исключена, потому что в её snapshot нет проигрываемого видео. На `/amongus-land/`, `/den-rozhdeniya-na-vr-arene/` и `/prazdnik-maxi/` проигрываются другие локальные или iframe-ролики, но без подтверждённой даты публикации они намеренно не размечены. Нативных индексируемых страниц в текущем snapshot-манифесте нет. |

`datePublished` и `dateModified` не используются: в данных нет достоверных дат публикации и обновления страниц. Обновление файла или дата миграции не являются датой публикации контента.

## Как добавить новую страницу

1. Создайте JSON страницы обычным для её типа способом. Не копируйте JSON-LD в `.astro`.
2. Заполните `slug`, `type` и `seo.title`, `seo.description`, `seo.keywords`, `seo.h1`. Мета-описание не копируется в JSON-LD автоматически: `WebPage.name` берётся из видимого H1, а `Service.description` квеста содержит только видимые характеристики. Это защищает разметку от исторических или противоречивых SEO-текстов.
3. Для квеста заполните видимые `hero.bg`, `hero.pills` (возраст, длительность, число игроков) и `venueSlug`. Площадка с таким `slug` должна существовать в `venues.json`. Генератор перенесёт возраст в `PeopleAudience`, длительность и число игроков — в читаемое описание `Service`. Связь `availableChannel` → `ServiceChannel` → `serviceLocation` появится только после того, как основной контент явно покажет адрес выбранной площадки. `audienceType` для вместимости не используйте: это тип целевой группы, а не количество участников. Цену и `offers` не добавляйте: точной цены квеста в данных нет.
4. Для площадки добавьте соответствующую запись в `venues.json` с адресом, `lat` и `lon`; на странице должны быть видны тот же адрес и часы работы. `hasMap` появится, только если точная ссылка `howto.routeUrl` действительно отрисована на странице.
5. Для FAQ добавьте секцию `kind: "faq"` только если выбранный layout действительно показывает её. У кастомного артборда источник должен быть тем же объектом, который использует его компонент.
6. Для нативного видео укажите `poster`, `src` и видимый `caption`. Для snapshot-плеера храните подтверждённые поля в `video.snapshot`: точный `id` из `data-source-video-id`, официальные `name`, `description`, `embedUrl`, `uploadDate`, `duration`, показанный `thumbnailUrl` и ссылки-доказательства `thumbnailSource`/`uploadDateSource`. `uploadDate` добавляйте только как ISO 8601 date-time с часовым поясом; без валидной даты генератор намеренно не создаёт `VideoObject`. Не подменяйте дату первой публикации датой копирования файла.
7. Проверьте, что изображение, FAQ, характеристики, адрес и видео действительно видны посетителю. Для snapshot-страницы `Layout.astro` принимает `video.snapshot` только при точном совпадении его `id` с единственным `data-source-video-id` отрисованного тела; отсутствие плеера или несовпадение исключает `VideoObject`. Общая разметка и разметка типа страницы подключатся автоматически через `src/lib/seo.js` и соответствующий layout.

## Что запрещено

- Нельзя размечать выдуманные цены или создавать `Offer` для квеста. Текст «точная стоимость — в форме бронирования» и внутреннее `priceFrom` без видимой цены не являются источником. Нельзя добавлять `availability` или сведения о НДС без такого же видимого подтверждения.
- Нельзя добавлять `Review` или `AggregateRating` о «Чё за Квест» и её площадках. Это собственный сайт организации; Google относит такую разметку `Organization`/`LocalBusiness` и их подтипов к self-serving reviews. Наличие настоящих и видимых отзывов не отменяет ограничение. Официальное правило: [Review snippet structured data](https://developers.google.com/search/docs/appearance/structured-data/review-snippet).
- Нельзя размечать скрытый FAQ, отзывы, видео или характеристики, которых посетитель не видит. Это нарушает [общие правила структурированных данных Google](https://developers.google.com/search/docs/appearance/structured-data/sd-policies).
- Нельзя придумывать `uploadDate`, `datePublished`, `dateModified`, рейтинг, число отзывов, адрес, координаты, соцсети или часы работы.
- Нельзя считать постер с кнопкой, ведущей на форму бронирования, доступным для просмотра видео.

## Локальная проверка

Быстрые проверки, которые не запускают сборку:

```bash
npm run verify:seo
node scripts/structured-data-audit.mjs
node scripts/structured-data-audit.mjs --report
```

Вторая команда должна завершиться сообщением `Structured data audit passed` для всего текущего набора индексируемых страниц. Валидатор проверяет сериализацию JSON-LD, обязательные поля и вложенные типы, пустые значения и заглушки, canonical-ссылки, координаты и часы площадок, факты квестов, видимые цены и FAQ, обязательный валидный ISO 8601 `uploadDate` с часовым поясом у каждого `VideoObject`, соответствие snapshot-метаданных видимому `data-source-video-id`, фактически запускаемому `data-rutubeid`, а также запрет self-serving review-разметки.

Перед объединением изменений, когда другие потоки не собирают проект, запустите полный гейт:

```bash
npm run ci
```

В полном гейте проверка запускается дважды: до сборки сверяет генераторы с snapshot-телом и данными, после каждой сборки команда `node scripts/structured-data-audit.mjs --dist` читает JSON-LD, canonical и фактически проигрываемое видео прямо из `<body>` каждого сгенерированного HTML-файла. У Rutube она проверяет согласованность `data-source-video-id` с приоритетным для runtime `data-rutubeid`, а затем сопоставляет идентификатор с `VideoObject.embedUrl`. У нативного ролика `contentUrl` сверяется с `data-video` либо фактическим `source`; thumbnail также должен совпасть с телом. В каждый запуск аудита дополнительно входит синтетический отрицательный контракт для подмены Rutube и нативного MP4. Поэтому подмена ролика в схеме или body делает прогон красным. `verify:production` дополнительно проверяет общий production-контракт.

IP-стенд `http://82.146.60.212` закрыт от индексации заголовком `X-Robots-Tag: noindex, nofollow`. На нём можно проверять наличие HTML-разметки, но canonical обязан оставаться на боевом домене, а окончательную проверку индексации проводят только после переключения домена.
