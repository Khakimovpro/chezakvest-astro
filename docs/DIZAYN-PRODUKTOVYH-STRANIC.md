# Дизайн продуктовых страниц

Дизайн-система используется нативными страницами квестов и праздников. Пилоты — `/igra_v_kalmara/` и `/kids/`. Контентная схема и подключение нативного режима описаны в [ПРОДУКТОВОЙ СТРАНИЦЕ](PRODUKTOVAYA-STRANICA.md). Спецификация реализации — волны A и B от 14 сентября 2026 года.

## Токены и поверхности

Источник значений — `src/styles/product/tokens.css`, подключённый из `src/styles/product.css`. Скоуп: корень `.product-page`, мобильная панель и лайтбокс страницы. Корнем может быть как `body`, так и вложенная обёртка праздника: стили внешних элементов учитывают оба случая.

| Роль | Токены и правило |
| --- | --- |
| Отступы | `--product-space-4/8/12/16/20/24/32/40/48/64/80/96` |
| Ритм | `section-y`: 56 → 96 px; `section-y-tight`: 24 → 44 px; `header-gap`: 28 → 48 px на 390 → 1440 |
| Контейнер | `container`: 1200 px, содержимое 1160 px; gutter 20 px, на 768–1239 — 32 px |
| Заголовки | Montserrat 800; display 36 → 64 px, h2 28 → 44 px; h3 Montserrat 700, 20 → 24 px |
| Текст | Nunito 400, body 16 → 17 px, lead 18 → 21 px; строки до 64ch |
| Действие | `accent` #ff6b00, текст `on-accent` #1f2933; hover #ff7d1a, press #f06200 |
| Читаемый оранжевый | `accent-ink` #b84a00 на светлом; `accent-on-ink` #ff8a00 на тёмном |
| Радиусы | поля sm 14 px, внутренние блоки md 16 px, карточки lg 24/20 px, панели xl 32/24 px, кнопки pill |
| Тени | shadow-1 карточки, shadow-2 панели, shadow-3 медиа и финальная форма, shadow-cta действие |

Секция получает ровно одну поверхность: `ground` показывает дудл body, `sheet` — белая, `ink` — #1c1c1c, `accent` — оранжевая. Последняя используется один раз перед подвалом. Соседние одноцветные секции обозначаются продолжением с `product-section--continue`. У общего `CardsRow` эту роль выполняет обёртка `product-cards-continue`.

Карточка наследует поверхность: на ground белая с shadow-1, на sheet приглушённая без тени, на ink приподнятая тёмная с тонким кольцом. Свойства `--product-context-*` передают цвет заголовка, подписи и иконки компонентам.

Числа в остальных правилах — токены либо фиксированная геометрия контролов, иконок, линий, колонок и брейкпоинтов. Новые числовые роли добавляются в начальный блок токенов с пояснением назначения.

## Иконки и текст

`Icon.astro` выводит inline SVG. Контуры Lucide 0.468.0 локальны: `product/icons/lucide.js`, лицензия ISC рядом. WhatsApp взят из существующего MessengerFab. Новой зависимости и запросов к CDN нет.

```astro
<Icon name="calendar-check" size={20} />
<Icon name="star" size={16} label="Рейтинг" />
```

Неизвестное имя прерывает сборку. Декоративные SVG скрыты от вспомогательных технологий; смысловая иконка получает `label` или соседний текст. Заливка разрешена у star, play и WhatsApp. Остальные контуры — 24×24, stroke 2, скруглённые концы.

Чтобы добавить иконку, скопируйте её внутреннюю разметку из той же версии Lucide в реестр и сохраните лицензию. Выберите существующее семантическое имя. `src/lib/product-icons.js` содержит общий `pickIcon(text, fallback)`: явное поле `icon` в данных имеет приоритет. Не добавляйте условия по slug. Проверка пилотных списков исключает случайный fallback `sparkles`.

`typograf()` сохраняет текст, заменяет дефис между числами на тире и связывает короткие слова неразрывным пробелом. Он возвращает текст для обычного экранирования Astro. Заголовки и лиды общих замороженных блоков типографируются в вызывающем макете, если доступен строковый проп.

## Компоненты

| Компонент | Назначение |
| --- | --- |
| ProductSectionHeader | eyebrow, title, lead, titleTail, id и слот aside. Лид со строчной буквы становится продолжением заголовка |
| ProductButton | ссылка или кнопка; primary, secondary, ghost, on-ink, on-photo, on-accent; размеры lg/md/sm; icon, iconEnd, block |
| ProductFactChip | факт с иконкой, скрытой смысловой подписью и опциональной ссылкой |
| ProductIconList | строки или `{t,sub,icon}`; inline/tile/check, одна или две колонки |
| ProductInfoCard | некликабельная карточка факта; иконка или номер шага; наследует поверхность |
| ProductMediaCard | изображение с фиксированными пропорциями, обводкой и иконкой увеличения; контракт `data-zoom` общего лайтбокса |
| ProductStars | пять SVG-звёзд с доступной подписью оценки |
| ProductGallery / ProductPlayers | горизонтальная лента / сетка с раскрытием дополнительных фото |
| ProductVideo | один или несколько HLS-роликов, содержательные факты и действие |
| ProductReviews | колонки на ПК, лента на телефоне; имя, источник, дата, полный текст и площадка |
| ProductPackages | вкладки с клавиатурой; карточки в сетке или ленте, выделенный пакет |
| ProductTimeline / ProductStats | последовательность праздника / панель подтверждённых чисел |
| ProductFaq / ProductMap | нативный details и карта, которая загружается по клику |
| MobileCtaBar | появляется после героя, скрывается возле брони, формы и квиза |

```astro
<section class="product-section product-section--ground">
  <div class="container">
    <ProductSectionHeader
      title="Что входит в праздник"
      lead="Выберите подходящий формат вместе с менеджером."
    />
    <ProductIconList items={page.included} variant="tile" columns={2} />
    <ProductButton href="#prazdnik" size="lg" icon="arrow-right" iconEnd block>
      Узнать стоимость
    </ProductButton>
  </div>
</section>
```

Этот пример задаёт оформление. Факты новой страницы всегда берутся из её подтверждённых данных.

## Движение и доступность

`product-motion.js` подключён к двум макетам. Контент виден изначально. Скрипт помечает только узлы ниже первого экрана; IntersectionObserver раскрывает их один раз. `data-product-reveal` означает одиночный блок, значение `group` — группу карточек с задержкой до четырёх шагов по 50 мс. Ленты получают один маркер на контейнере. Первый экран, все ProductSectionHeader, шапка и подвал остаются без reveal. Появление контента длится 480 мс, смещение 12 px, на телефоне 8 px; порог наблюдения −6%.

Пространственное движение использует opacity и transform. Цвет, тень и прозрачность интерактивных элементов меняются за 160 мс; FAQ-шеврон поворачивается за 220 мс. Высота FAQ — отдельное разрешённое исключение с нативным `details`; браузер без поддержки плавного раскрытия показывает ответ сразу. Под `prefers-reduced-motion: reduce` содержимое сразу видно. Печать, уход вкладки в фон и переключение системной настройки освобождают ожидающие узлы. Фокус внутри ожидающего блока тоже раскрывает его.

Hover с движением действует только для точного указателя. Некликабельные карточки не поднимаются при наведении. Фокус виден двойным кольцом. Во вкладках стрелки, Home и End перемещают фокус и включают мгновенную смену; клик перемещает оранжевый индикатор. Герой анимирует только масштаб фото, текст и кнопки неподвижны.

Плеер не показывает системные контролы до клика; после старта включает их. Одновременно играет одно видео. Размеры кадра определяет HLS-реестр, у изображений заранее задана геометрия.

## Общие компоненты и календарь

PartyForm, CallbackForm, PrebookingForm, CardsRow, LazyMap и Lightbox используются по всему сайту. Их разметка и поведение сохранены; продуктовые стили ограничены корнем страницы. Форма получает лист, подписи над полями, Nunito в полях и кнопку без капса. Поля, обязательность, получатель и результат отправки сохраняются.

Календарь использует настоящие классы сервиса: `.quest_line`, `.row_quest`, `.col-xs-2_quest`, `.col-xs-10_quest`, `.time_quest`, `.label_quest`. Оболочка `.product-schedule` задаёт светлую панель и стилизует слоты. На телефоне — пять слотов в строке, цель от 44 px высотой. Псевдоэлементы очистки float выключены внутри новой grid-строки. Семь дней, раскрытие следующих семи дат за клик, обработчики брони и резервная заявка при ошибке либо восьмисекундном ожидании сохраняются.

`MobileCtaBar` учитывает локальный MessengerFab и внешний YourGood. Локальная кнопка имеет 56×56 px; внешний виджет сохраняет свои 64×64 px. После загрузки виджета компонент добавляет только правило смещения его кнопки в открытый shadow root. Смещение приходит из CSS-переменной на `pf-widget`, действует ниже 768 px при видимой панели и меняется мгновенно. Всплывающие окна виджета сохраняют исходное положение.

Общий Lightbox сохраняет моментальную смену фотографии, общий CardsRow — свои SVG-контуры и обработчики прокрутки. ProductQuestPage подключает `rows.js`. В календаре перехват кнопки выполняется только внутри ProductBooking: после 7 видимых дней каждый клик добавляет ещё 7; последняя порция скрывает кнопку. Резерв до загрузки равен 636 / 1024 / 1210 px для ПК / планшета / телефона; при появлении строк снимается. Свободные слоты используют accent-soft и accent-ink, при наведении — accent и on-accent. Денежные подписи используют `receipt-russian-ruble`.

## Уточнения компонентов волны B

`--product-hero-shade-floor` задаёт нижнюю границу затемнения: 8% у квеста, 55% у праздника до 1024 px. Там используется вертикальный градиент. На широком экране лид ограничен 40ch; мера H1 праздника — 10.4em. Надзаголовок на фотографии белый с непрозрачностью 88%. `--product-accent-display: #e85a00` предназначен для хвостов заголовков от 24 px жирным и графики рейтинга; мелкий оранжевый текст сохраняет accent-ink. `--product-media-scrim` — общий нижний градиент подписей фото с остановками 35 / 62 / 100% и непрозрачностью 0 / 55 / 88%.

ProductShort на ПК делит пространство 4fr / 8fr с зазором 64 px: заголовок слева, абзацы справа. Все абзацы ProductStory ограничены 36rem, вводный отделён снизу 24 px. Переносы строк в подписях IconList и InfoCard сохраняются. Одиночный текст с иконкой центрируется; при наличии подписи первая строка заголовка выравнивается с центром квадрата.

ProductFit — панель sheet-muted с радиусом xl, отступами 40 / 32 / 24 px на ПК / планшете / телефоне. На ПК две колонки с разделителем; на телефоне два последовательных списка. Галочки внутри белых кругов 28 px относятся только к этой панели.

В лентах фото и CardsRow первая карточка совпадает с краем контента, трек доходит до правого края окна. С 768 px стрелки стоят парой над треком; заголовок оставляет место для них. Крайняя стрелка имеет opacity .35; при отсутствии переполнения обе скрыты. На телефоне управление свайпом. Общие карточки получают типографированные входные подписи в продуктовом макете.

Правило планшета 768–1023: текстовая колонка уже 360 px требует вертикальной композиции. FAQ, формы, финал и квиз становятся столбцом; три информационные карточки и шаги — строками. Исключение из спецификации: единственный ролик занимает 300 px при зазоре 40 px. Залы переходят в ленту с карточкой 44%; на телефоне ширина 86%. Оснащение имеет подпись и пункты в именительном падеже.

Отзывы: оценка площадки — одна цифра после запятой, число отзывов отделено точкой, `2Gis` отображается как «2ГИС». Склонение считает `pluralRu()`. На телефоне чипы идут одной строкой высотой 44 px, все карточки доступны в ленте и имеют общий нижний край. JS ограничивает только длинный текст семью строками и добавляет «Читать полностью / Свернуть» с aria-expanded; при ширине от 768 px и без JS текст полный. Шапка карточки всегда двухколоночная, звёзды под метой.

Типограф связывает вперёд только служебные слова, частицы «ли/же/бы» — назад, местоимения оставляет самостоятельными. Он нормализует тире, сокращения адресов, число с единицей и короткие дефисные слова. Применяется к подписям карточек, карты, залов, пакетов и плиток. FAQ сохраняет исходный текст для совпадения с FAQPage. Тесты покрывают шесть примеров B-SPEC и повторное применение без изменения результата.

Чекбокс согласия стоит на одной вертикали с полями; общий компонент формы сохранён. Фокус полей получает внутреннее кольцо accent-ink 2 px и наружное мягкое кольцо 4 px. Фокус FAQ скруглён по radius-xs. Подписи плиток: 16 / 15 / 13 px на ПК / планшете / телефоне, без разрыва слова посередине.


## Новая страница

1. Подготовьте подтверждённые данные по контентной схеме и включите `render: "native"`.
2. Соберите разделы существующими компонентами. Пустые разделы не выводите.
3. Укажите `surface` и объявите продолжения; используйте одну финальную accent-полосу.
4. Подберите явные ключи иконок для неоднозначных фактов, задайте изображения и зарегистрированные HLS slug.
5. Проверьте мобильную и широкую страницу, клавиатуру, reduced motion и работу без JavaScript. Затем выполните тесты продукта, SEO-аудит и сборку.

Используем одну шкалу отступов, семантические иконки, поверхностные токены и компоненты. Избегаем чисел оформления в JSON, CSS по slug/id, текстовых символов вместо иконок, скрытого до загрузки JS контента, новых npm-зависимостей для движения и изменения замороженных форм ради внешнего вида.
