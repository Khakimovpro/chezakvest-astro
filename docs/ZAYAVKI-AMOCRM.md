# Заявки сайта в amoCRM

Нативные формы `data-lead-form` и формы Tilda отправляют JSON на `/api/lead`.
nginx ограничивает частоту до 6 запросов в минуту на IP с burst 3 и передаёт запрос сервису
Python 3.12 на `127.0.0.1:8790`. Зависимости сервиса — стандартная библиотека Python.

После `200 {"ok":true}` посетитель попадает на `/kids_spasibo/?form=…` для `pageType=holiday`,
на `/spasibo/?form=…` для остальных страниц. Обе страницы нативные, `noindex, follow`, исключены
из sitemap; старые редиректы удалены из CSV и артефакты пересозданы генератором.
При ошибке сети, неуспешном HTTP или некорректном подтверждении под формой показываются телефон
и ссылка WhatsApp из `site.json`. WhatsApp автоматически не открывается. Локальные квизы и exit-intent используют тот же отправитель.
В exit-intent имя не запрашивается: контакт подписан «Обратный звонок», это явно отмечено в примечании.

Контекст берётся из публичных JSON страниц и реестра площадок: тип, слаг, название квеста и
адрес по `venueSlug` (дубли карточек квеста на других площадках не меняют эту привязку).
Клиент сохраняет первое касание на 30 дней: UTM, yclid, gclid, utm_referrer, document.referrer.
Прямой или повторный рекламный заход внутри этого срока не затирает первое касание.
`_ym_uid` и `roistat_visit` читаются из cookie при отправке. Запрет localStorage не блокирует форму.
Время `startedAt` — первый фокус внутри формы. Быстрее 3 секунд или заполненный `website` дают
тихий успех без создания заявки. Формы Tilda сохраняют свои маски и ошибки; дата необязательна.

Сервис принимает только JSON до 8192 байт. Имя 2–80 символов, российский телефон нормализуется
в +7 и 10 цифр, дата ISO необязательна, комментарий до 1000 символов, согласие строго `true`.
Origin либо Referer обязателен; каждый присутствующий заголовок должен иметь разрешённый хост.
Список задаётся `LEAD_ALLOWED_HOSTS`. Контрольные символы и HTML удаляются. Текст с ведущими `=`, `+`, `-`, `@`, табуляцией или переводом строки получает префикс `'` перед отправкой в amo. Телефон передаётся только нормализованным в PHONE контакта, в примечание не дублируется. Логи не содержат
имени, полного телефона, текста заявки или заголовков авторизации.

Карта находится в `leads/amo-map.json`. Значения select сопоставляются по точному тексту enum,
для адресов предусмотрен явный словарь соответствий написанию в CRM. Неизвестные значения
не заполняются в select, но остаются в примечании. Карта подтверждается только GET-запросами:
`python3 leads/proverit_kartu.py`. Поля и enum проверены в реальном аккаунте 14.09.2026.

Контакт ищется по телефону; среди результатов проверяется точное нормализованное совпадение.
Если его нет, создаётся контакт. Сделка связывается с найденным/новым контактом, получает теги
«Сайт», «Ростов», вид формы и название квеста/страницы. Примечание содержит страницу, форму,
все переданные метки, дату, комментарий, платформу/браузер и время по Москве.
Формат запросов соответствует [API сделок](https://www.amocrm.ru/developers/content/crm_platform/leads-api)
и [API контактов](https://www.amocrm.ru/developers/content/crm_platform/contacts-api).

Обычная воронка и статус задаются `AMO_PIPELINE_ID=6429238` и `AMO_STATUS_ID=54964090`.
Для смены изменить защищённый env на сервере и перезапустить сервис. Следующая установка
восстановит значения из `deploy/leads/env_stdin.py`, поэтому для постоянного изменения обновить
также этот источник. `AMOCRM_SUBDOMAIN` и `AMOCRM_TOKEN` хранятся только в защищённом окружении.

Номер `LEAD_TEST_PHONE` (по умолчанию +79000000000) всегда направляется в тестовую воронку
5519260 / 48805513, тег «ТЕСТ сайта», затем статус 143. Живую проверку выполняет R.
L использует исключительно локальный поддельный сервер для POST/PATCH.

Перед запросом в amo заявка атомарно сохраняется в `queue/*.json` с правами 600. Короткая блокировка приёма защищает запись и дедупликацию; отдельная блокировка доставки
общая для HTTP-процесса и таймера. При занятой доставке новый запрос уже сохранён и сразу
подтверждается клиенту; повтор заберёт его по таймеру. Один нормализованный телефон не создаёт вторую
сделку в течение 10 минут независимо от хоста, пути и параметров URL. Пока заявка в очереди,
повтор также подавляется. ID контакта, сделки, закрытие теста и примечание сохраняются по этапам:
сбой на примечании не создаёт ещё одну сделку. Подтверждённые квитанции `done` не содержат ПДн
и удаляются таймером после 10 минут.

Перед каждым созданием сделки сервис под общей блокировкой доставки сохраняет квоту в `quota.json`: максимум 3 попытки создания на телефон за скользящие 24 часа и 40 на весь сервис за скользящий час. Квота содержит только SHA-256 телефона и время; старые записи отбрасываются при следующей попытке. Неоднозначный результат POST также расходует квоту, поскольку сделка могла создаться. Повтор примечания или закрытия уже известной сделки квоту не расходует. Ограничения действуют и для тестового номера.

Превышение сохраняет заявку в `hold/` (600, каталог 700) и пишет `CRITICAL LEAD HOLD` с причиной и хешем, без телефона. Таймер не отправляет hold автоматически; владелец разбирает их вручную. Повтор того же телефона при наличии hold подавляется, содержимое удержанной заявки сохраняется.

Сетевая ошибка, 5xx, 401 и другие ошибки amo оставляют заявку в очереди с ошибкой в журнале.
Таймер `chezakvest-leads-povtor.timer` запускает `povtor.py` раз в 5 минут. Через 24 часа заявка
перемещается в `failed/`, пишется CRITICAL. Файлы failed сохраняются для ручного разбора.
Если недоступно само хранилище, сервис отвечает 503: клиент показывает запасные контакты.
При обрыве ответа после успешного POST в amo результат может быть неопределённым: если ID
не получен, повтор способен создать дубль. API request_id не обеспечивает идемпотентность;
это ограничение внешней границы, которое нужно учитывать при ручном разборе сетевых сбоев.

Установка, последовательность относительно выкладки сайта и откат —
[`deploy/leads/README.md`](../deploy/leads/README.md). Health отражает работу HTTP-сервиса,
доставку в amo проверяют по очереди и журналу; успешный health сам по себе её не подтверждает.

Локальные проверки:

```bash
python3 -m unittest discover leads/tests
node --test tests/lead-form.test.mjs tests/lead-form-browser.test.mjs tests/lead-context.test.mjs
bash deploy/leads/ustanovit.sh --dry-run
npm run verify:redirects
flock /tmp/chezakvest-sborka.lock bash -c 'npm run build && LEAD_E2E=1 node --test tests/lead-e2e.test.mjs && npm run verify:production'
```

E2E запускает отдельные fake amo, HTTP-сервис на 8790 и прокси над `dist/`; закрывает их после
проверки. В обычном `npm run test` этот сценарий пропускается, чтобы не читать общий `dist/`
одновременно с чужой сборкой. Полный браузерный сценарий запускается отдельно под замком.
