# Установка сервиса заявок (поток R)

Из корня репозитория: `bash deploy/leads/ustanovit.sh --dry-run`, затем `bash deploy/leads/ustanovit.sh`.
L проверяет локально; установку и живую тестовую заявку выполняет R.

Установщик использует SSH `root@82.146.60.212` и `~/.ssh/chezakvest_key`. Он создаёт пользователя
`chezakvest-leads`, доставляет Python stdlib-сервис в `/opt/chezakvest-leads`, systemd units и зону
`/etc/nginx/conf.d/chezakvest-leads.conf`. Секреты читает из `/home/claude/che_za_kvest/.amo.env`
и передаёт через stdin SSH в `/etc/chezakvest-leads/leads.env` (root, 600). Временного файла секретов
на рабочей машине нет. `env_stdin.py` отдельно не запускать: его stdout предназначен только для SSH.

Порядок обязателен: **установщик сервиса и зоны → обычный релиз сайта через согласованный CI/CD →
проверка `/api/lead/health` → заявка тестовым телефоном**. Новый `chezakvest-common.conf` ссылается на
зону, поэтому доставлять его до установки зоны нельзя. Существующий механизм доставки сайта
описан в `deploy/README.md`; установщик сайта здесь не заменяется.

`LEAD_TEST_PHONE=+79000000000` идёт в воронку 5519260, статус 48805513, получает тег «ТЕСТ сайта»
и сразу закрывается статусом 143. Все остальные номера идут в 6429238 / 54964090.
При проверке формы выждать не меньше 3 секунд после первого фокуса.

Повторная установка обновляет файлы и перезапускает сервис. Очередь сохраняется.
Проверки после установки: `systemctl status chezakvest-leads`,
`systemctl list-timers chezakvest-leads-povtor.timer`, `journalctl -u chezakvest-leads -u chezakvest-leads-povtor`.
Health проверяет доступность процесса, без запроса в amo и без раскрытия настроек.

Откат: `bash deploy/leads/ustanovit.sh --off`. Перед удалением зоны установщик снимает строки
`limit_req zone=chezakvest_leads` с её потребителей в общем конфиге сайта, проверяет nginx и
перезагружает его. Затем останавливает сервис и таймер. Прокси-маршруты остаются: ответ 502
показывает посетителю телефон и WhatsApp. Нельзя удалить зону, оставив `limit_req` на неё:
это сломает следующий `nginx -t`. Для возвращения новой версии повторить установку сервиса,
затем доставку конфига сайта с лимитами. Очередь и failed-файлы откат не удаляет.

Состояние: `/var/lib/chezakvest-leads/{queue,done,failed}`. Это данные заявок; в релизный архив сайта
они не входят. Доступ только сервисному пользователю/root. После 24 часов без доставки заявка
остаётся в `failed`, требует ручного разбора владельцем и не удаляется автоматически.

После `--off` **до любого штатного отката сайта на релиз с API** снова выполнить
`bash deploy/leads/ustanovit.sh`: сохранённый nginx-снимок такого релиза содержит ссылку на зону.
Без восстановления зоны штатный rollback будет отменён на `nginx -t`. Отключение сервиса и
откат к релизу с API не совмещать без этого шага. Это обязательная зависимость процедуры;
`deploy.sh` и формат сохранённых снимков в потоке L не менялись.
