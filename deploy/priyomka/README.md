# Приёмка HTTP-стенда

Повторяемая read-only проверка сравнивает зафиксированный манифест принятого локального `dist/`
с активным релизом, запрашивает все URL из sitemap и legacy-карты, проверяет заголовки и краевые
пути, делает по пять замеров трёх страниц с dev-сервера и московского сервера, а затем запускает
`npm run verify:live`.

Запуск из корня репозитория:

```bash
node deploy/priyomka/verify-stage.mjs
```

По умолчанию используются `http://82.146.60.212`, `root@82.146.60.212` и ключ
`~/.ssh/chezakvest_key`. Их можно заменить переменными `SITE_ORIGIN`,
`CHEZAKVEST_SSH_TARGET` и `CHEZAKVEST_SSH_KEY`. Команда ничего не меняет на сервере: SSH нужен
только для чтения файлового манифеста и замеров `curl` через loopback.

Каждый запуск перезаписывает TSV/JSON/TXT-результаты в этой папке. Нулевой код выхода означает,
что все проверяемые контракты выполнены; любое расхождение перечисляется в консоли и
`summary.json`.

`release-baseline.json`, `release-manifest.tsv` и `release-sitemap.tsv` фиксируют последний
осознанно принятый локальный `dist/`. Обычный запуск проверки их не обновляет: новый baseline
снимают только после ожидаемого изменения релиза, сверяют его числа и причину diff, а затем снова
запускают полную приёмку. Поэтому случайная сборка в общем `dist/` не меняет предмет проверки.
