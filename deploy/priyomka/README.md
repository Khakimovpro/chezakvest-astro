# Приёмка HTTP-стенда

Повторяемая read-only проверка сравнивает зафиксированный манифест принятого локального `dist/`
с активным релизом, запрашивает все URL из sitemap и legacy-карты, проверяет заголовки, краевые
пути и реальные изображения типовых страниц, делает по пять замеров трёх страниц с dev-сервера
и московского сервера, а затем запускает `npm run verify:live`. Ресурсная выборка охватывает
главную, каталог и все JSON-типы страниц; для шести площадок дополнительно выбираются изображения
`/assets/q/`, из-за прав которых nginx раньше отвечал `403`. Результат пишется в `resources.tsv`.

Запуск из корня репозитория:

```bash
node deploy/priyomka/verify-stage.mjs
```

По умолчанию используются `http://82.146.60.212`, `root@82.146.60.212` и ключ
`~/.ssh/chezakvest_key`. Их можно заменить переменными `SITE_ORIGIN`,
`CHEZAKVEST_SSH_TARGET` и `CHEZAKVEST_SSH_KEY`. Команда ничего не меняет на сервере: SSH нужен
только для общего lock, чтения файлового манифеста и замеров `curl` через loopback. Lock не даёт
выкладке или cutover сменить активный релиз во время приёмки.

Каждый запуск перезаписывает TSV/JSON/TXT-результаты в этой папке. Нулевой код выхода означает,
что все проверяемые контракты выполнены; любое расхождение перечисляется в консоли и
`summary.json`. До долгих проверок скрипт через SSH сверяет отпечаток зафиксированного манифеста
`path + size` с содержимым активного каталога и требует его `.deploy-verified`. Если содержимое
отличается, приёмка сразу записывает `FAIL`, требует новый baseline и не может выдать устаревший
`PASS`. Имя релиза и commit остаются в отчёте как справочная metadata: их расхождение с baseline
не мешает проверке, когда отпечаток содержимого совпал.

`release-baseline.json`, `release-manifest.tsv` и `release-sitemap.tsv` фиксируют последний
осознанно принятый локальный `dist`; имя release и commit описывают происхождение этой копии.
Обычный запуск проверки их не обновляет: новый baseline
снимают только после ожидаемого изменения релиза, сверяют его числа и причину diff, а затем снова
запускают полную приёмку. Поэтому случайная сборка в общем `dist/` не меняет предмет проверки.
