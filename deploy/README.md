# Выкладка сайта на московский сервер

Скрипт запускается только из корня репозитория. Для обычного релиза нужен чистый Git и доступ к
`root@82.146.60.212` ключом `~/.ssh/chezakvest_key` (другой путь можно передать через
`CHEZAKVEST_SSH_KEY`).

## Релиз одной командой

```bash
deploy/deploy.sh
```

Скрипт запускает полный `npm run ci`, заново собирает `dist/`, повторно проверяет неизменность
исходников, добавляет в него `version.json`, передаёт сборку во временный каталог через rsync и
проверяет её контрольными суммами. Только после проверки каталог получает окончательное имя,
а файлы на сервере принадлежат `root:root`. Затем скрипт атомарно переключает
`/var/www/chezakvest/current`, проверяет и перезагружает nginx, выполняет HTTP-смоук и оставляет
три последних релиза. При ошибке после переключения `current` автоматически возвращается на
предыдущий релиз. Только зелёный релиз получает внутренний маркер `.deploy-verified`; откат
игнорирует все каталоги без него.

Полезные режимы:

```bash
deploy/deploy.sh --dry-run
deploy/deploy.sh --skip-gate
deploy/deploy.sh --allow-dirty
```

`--dry-run` только показывает план. `--skip-gate` допустим, когда этот же коммит уже прошёл полный
гейт; отдельная сборка всё равно выполняется. Грязное дерево блокирует релиз, пока оператор явно не
передаст `--allow-dirty`.

## Откат одной командой

```bash
deploy/deploy.sh --rollback
```

Откат выбирает последний сохранённый релиз, отличный от активного, атомарно направляет на него
`current`, выполняет `nginx -t`, перезагружает nginx и повторяет HTTP-смоук. Если проверка
отката не проходит, исходный `current` восстанавливается автоматически. План отката можно
посмотреть через `deploy/deploy.sh --rollback --dry-run`.

## Размещение на сервере

- релизы: `/var/www/chezakvest/releases/<UTC-время>-<короткий-коммит>`;
- активный релиз: `/var/www/chezakvest/current`;
- конфигурация nginx: `/etc/nginx/sites-available/chezakvest.conf`;
- legacy-редиректы: `/etc/nginx/snippets/chezakvest-legacy-redirects.conf`;
- ACME webroot: `/var/www/acme/.well-known/acme-challenge/`;
- логи: `/var/log/nginx/chezakvest.access.log` и `/var/log/nginx/chezakvest.error.log`.

Перед заменой существующих файлов nginx скрипт сохраняет рядом копии с суффиксом
`.bak-<UTC-время>`. Стандартный `/etc/nginx/sites-enabled/default` отключается, но исходный файл
`/etc/nginx/sites-available/default` остаётся на месте.

## Когда домен укажет на сервер

После переключения DNS нужно заменить `server_name _` на
`xn--80aehcht5ci1b.xn--p1ai`, проверить доступность ACME-файла и выпустить сертификат через
Certbot. После проверки HTTPS следует настроить единый канонический HTTPS-хост и HTTP-редирект,
повторить строгий живой смоук, затем убрать `X-Robots-Tag: noindex, nofollow`. HSTS включается
только после подтверждённой работы HTTPS; CSP — только после отдельного тестирования инлайновых
стилей и скриптов. До этого текущая конфигурация намеренно остаётся HTTP-стендом без HSTS и CSP.

После появления в серверном конфиге `listen 443` или `ssl_certificate` текущий stage-скрипт
остановится до сборки и не перезапишет TLS-настройки. Перед следующим production-релизом нужно
согласовать постоянный способ управления HTTPS-конфигом и его откатом; автоматически смешивать
стендовую и боевую конфигурации скрипт намеренно не пытается.
