# Переключение домена на московский сервер

DNS-зону `чезаквест.рф` сейчас обслуживает Beget (NS `ns1.beget.ru` и связанные серверы), а
DNS-зону `chezakvest.ru` — REG.RU (NS `ns1.reg.ru`, `ns2.reg.ru`). Перед изменением сохраните
скриншот или экспорт текущих записей в каждой затрагиваемой панели — он нужен для быстрого
возврата на Tilda.

В панели Beget откройте DNS-зону и замените только A-записи:

| Панель | Имя | Значение |
| --- | --- | --- |
| Beget, зона `чезаквест.рф` | `@` | `82.146.60.212` |
| Beget, зона `чезаквест.рф` | `www` | `82.146.60.212` |
| REG.RU, зона `chezakvest.ru`, если этот домен тоже переводим | `@` | `82.146.60.212` |
| REG.RU, зона `chezakvest.ru`, если этот домен тоже переводим | `www` | `82.146.60.212` |

Скрипт обязательно ждёт основной домен. Дополнительные имена он автоматически добавит в
сертификат только тогда, когда их единственная A-запись уже указывает на новый сервер. Обычно
изменение видно через несколько минут, но из-за TTL распространение может занять до 24 часов.
Проверить можно командой `dig +short A имя-домена`: в ответе должен остаться только
`82.146.60.212`. Если у веб-имени есть AAAA-запись, удалите её: на новом сервере IPv6 не
настроен, а центр сертификации может выбрать старый IPv6-адрес и не подтвердить домен.

После распространения DNS из корня репозитория запустите одну команду:

```bash
deploy/enable-domain.sh
```

Успех — скрипт завершился сообщением `Переключение домена завершено успешно`, главная открывается
по `https://чезаквест.рф`, альтернативные имена перенаправляют на неё, а финальный
`npm run verify:live` зелёный. План без изменений можно посмотреть через
`deploy/enable-domain.sh --dry-run`.

Если что-то пошло не так, скрипт сам возвращает предыдущую конфигурацию nginx. Ручной повторный
откат: `deploy/enable-domain.sh --rollback`. Чтобы вернуть посетителей на Tilda, восстановите в
Beget и, если меняли `.ru`, в REG.RU **точные прежние A-записи со сделанных скриншотов/экспортов**
и дождитесь их распространения.
После включения HSTS некоторые браузеры будут обращаться к домену только по HTTPS, поэтому у
возвращённого хоста Tilda должен оставаться рабочий сертификат.

MX, TXT, SPF, DKIM, DMARC и остальные почтовые записи не меняйте и не удаляйте: замена A-записей
сайта сама по себе не требует переноса почты. Если почтовый MX ссылается на имя внутри этого же
домена, отдельно убедитесь, что A-запись именно этого почтового имени не была изменена.
